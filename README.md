# CardioHealth: diabetes risk screening web app

A web app with two checks. The **lifestyle check** needs only questions a person can answer (age, sex, BMI, blood pressure history, general health, exercise, diet and so on). The **clinical check** uses a 2-hour glucose test result. Both show a live risk gauge, four risk bands, a risk curve you can explore, what-if scenarios, a printable PDF report and batch scoring of CSV files.

It is plain HTML, CSS and JavaScript. No server, no database, no internet. The trained models are lists of numbers inside `web/js/models.js` and the page does the maths itself, so nothing a person types ever leaves their computer.

## Two editions

| | Lecturer edition | Patient edition |
|---|---|---|
| File | `CardioHealth-Lecturer.html` | `patient/index.html` |
| For | Your supervisor and defence | Real users, to deploy and push to GitHub |
| Tabs | Assessment, Batch, Models, Backend, About | Your check, About |
| Wording | Technical, with model details and limits | Plain language, no model details |
| PDF report | Full report with model metrics and limits | One clean page: result, answers, key factors, next steps, one-line disclaimer |
| Source code inside | Yes (shown on the Backend tab) | No |

Both are built from the same code by `python -m src.run`, so they always give identical estimates. The patient file keeps only what a patient needs to get a result.

## Open the lecturer edition now

1. **Extract the whole zip first** (right-click, Extract All). Do not open files from inside the zip viewer: it unpacks only the one file you click, and the app then loses its styles and scripts.
2. Double-click **`CardioHealth-Lecturer.html`**. It is the entire app in one file, so it works from any folder, a USB stick or an email attachment, with no internet.

`web/index.html` is the same app split into separate files (easier to read and edit). It needs the `css/` and `js/` folders beside it. If it cannot find them it shows a red warning at the top of the page.

## Deploy the patient edition to GitHub

The folder `patient/` is everything you push. It holds `index.html` and a short `README.md`.

1. Create a new GitHub repository and upload the two files from `patient/`. Do not upload the rest of this project, so the datasets, Python code and lecturer material stay private.
2. In the repository's Settings, open Pages, choose "Deploy from a branch", pick `main` and `/ (root)`, and save.
3. After a minute GitHub shows the public address.

Menu names on GitHub change from time to time. Netlify Drop, Cloudflare Pages and Vercel also work: no build command, publish the folder.

## Rebuild and test

```bash
pip install -r requirements.txt
python -m src.run               # about 2 minutes; rewrites web/js/models.js, code.js, models/, CardioHealth-Lecturer.html and patient/
python -m pytest                # 8 Python checks
npm install                     # one time, for the browser tests
node tests/parity.test.js       # JavaScript gives the same answers as scikit-learn
node tests/ui.test.js           # clicks through the real page in a simulated browser
node tests/single.test.js       # the lecturer file works alone in an empty folder
node tests/patient.test.js      # the patient edition is clean, works, and has no lecturer material
```

Last run: 8 Python tests pass; both single-file editions work alone in an empty folder, and the patient file contains no lecturer wording, model details or source code; the browser maths matches scikit-learn on 200 clinical and 300 lifestyle people (largest difference under 1e-15); 55 interface checks pass. The page was also opened in a real Chromium browser from a `file://` path with no console errors, and checked at desktop and phone width.
